---
title: 运行模式
description: 把一个系统自己的代码运行两次，一次保持发布时的原样，一次切断某条通路或某个证据步骤，再比较结果。
---

运行模式的做法类似 A/B 测试。HALO 在固定输入上运行一个系统公开发布的代码，一次不做修改，一次切断选定的通路或证据步骤，然后比较两次的输出。代码中只替换模型客户端，让系统改为调用同一个基座模型，这个模型在两次运行中保持不变。最后由盲评比较输出，也就是评判模型不知道哪份输出来自哪次运行。

## 为什么用 A/B 测试

资料可以说明一条通路已经实现，却说明不了它是否起作用。在论文中，AiGet 通过两条路径把用户画像传给行动模块。只切断其中任意一条时，评判模型没有明显偏好。两条都切断后，评判模型更偏好原始的建议。要在不依赖系统自我描述的前提下看到这类效果，唯一的办法是把通路逐条切断，也一起切断。

## 切断点

每个案例（为一个系统准备的一套运行配置）都会声明每条通路或每个证据步骤在系统代码中经过的位置，并在接收端切断它：

- 切断通路，就是扣下经过这条通路的内容，例如把送到行动模块的检索记忆清空（M→A）。
- 切断证据步骤的做法沿用 EAIA 案例：修订步骤看不到行动（记录），收不到反馈（结果），收到的反馈被对应到错误的行动上（归因），或者照常运行但不写入结果（修订，这一切断也覆盖后续使用）。

## 如何运行

```bash
uv venv cases/aiget/.venv -p 3.11
uv pip install -p cases/aiget/.venv/bin/python -r cases/aiget/requirements.txt
halo run cases/aiget --workers 4
```

测试框架把每次运行的输出、评判模型的判定和一份汇总写入 `runs/<case>/<name>/`。[开发者](/HALO/zh-cn/developers/)页面说明了如何添加案例。

## 结果

论文的运行模式测试针对研究系统 [AiGet](/HALO/zh-cn/results/research/)，以及公开了代码的产品 [EAIA](/HALO/zh-cn/results/products/)。

## 闭源产品

没有公开代码的产品无法在内部切断，但同样的设计仍可以用在产品的边界上。做法是用同一组预先写好的输入运行两次，一次打开产品提供的某个开关，一次关掉它，再让评判模型比较。这类开关包括记忆、已连接的插件或反馈等。[轨迹能说明什么](/HALO/zh-cn/architecture/trust/)介绍了这种做法如何与插件结合。
