HALO 全称 Harness for Always-On Loop Oversight，即持续在线闭环监督工具。它检查一项持续在线的个人服务如何形成闭环。HALO 沿用综述 *Always-On Personal Intelligence*（持续在线个人智能）的框架：一项服务是由感知、记忆和行动三个模块组成的闭环，模块之间由信息流通路相连。会自我改进的服务还需要一条证据链，从它自己的记录一直延伸到它之后用上的一次修订。[持续闭环](/HALO/zh-cn/concepts/loop/)一页定义了这些术语。

## 使用 HALO 的三种方式

| | 只读模式 | 运行模式 | 插件 |
|---|---|---|---|
| 考察对象 | 系统的论文、文档和代码 | 系统已公开的代码，在固定输入上运行 | 正在运行的智能体，通过它记录的步骤 |
| 回答的问题 | 来源是否报告了每条通路和每个证据步骤？ | 切断一条通路或一个步骤，输出会不会改变？ | 智能体做过的事里出现了哪些通路和步骤？ |
| 需要什么 | 来源材料 | 代码，以及把代码接入 HALO 的适配器 | 一个 MCP 连接 |
| 能否用于产品 | 可以，依据产品文档 | 只有代码已公开时才行 | 可以，在产品运行时 |

只读模式和运行模式是综述中的两种模式。插件是第三种方式，本文档主要介绍它。插件把 HALO 接到一个已经在运行的智能体上，例如一个 ChatGPT dot 或 Grok Bot，不需要访问智能体的代码。

## 插件如何工作

插件是一个 MCP 服务器。智能体连接插件后，在闭环中每走一步，就调用一个对应的工具：接收新内容时调用 `halo_observe`，存取记忆时调用 `halo_remember` 和 `halo_recall`，采取行动或决定保持沉默时调用 `halo_act`，得知一次行动的效果时调用 `halo_outcome`，改变自己的工作方式时调用 `halo_revise`。每次调用都写明新的一步用到了哪些更早的步骤。

HALO 把这些步骤保存在你机器上的账本里，再从步骤之间的引用读出闭环。`halo_report` 用与综述表格相同的术语返回结果：六条通路、五个证据步骤，以及轨迹（智能体记录下的全部步骤）支持的最高等级。[插件架构](/HALO/zh-cn/architecture/)逐一介绍各个部分。

## 报告能说明什么

步骤由智能体自己记录，所以报告显示的是智能体自称做过的事，以及这些步骤之间如何引用。HALO 检查的是引用，而不是这些步骤是否真的发生过。没有出现的通路或步骤会报告为“未观察到”，从不报告为“不存在”。等级是下界，实际等级可能更高。[轨迹能说明什么](/HALO/zh-cn/architecture/trust/)一页对此有详细说明。
