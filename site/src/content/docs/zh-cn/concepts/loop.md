HALO 使用论文 *Always-On Personal Intelligence*（持续在线个人智能）中的术语。本页给出插件所依赖的定义。只读模式使用同样的定义，完整写在 `halo/read/protocol/PROTOCOL.md` 中。

## 三个模块

一项持续在线的个人服务，是由三个功能模块组成的闭环。

- **感知（S）** 获取并解释当前的观察：用户输入、传感器数据流、屏幕状态、外部事件，以及观察到的服务自身执行状态。
- **记忆（M）** 在多次交互之间保留信息。
- **行动（A）** 选择服务的行为：保持沉默、沟通、准备或执行。

一个操作属于哪个模块，看它的功能，而不看组件叫什么。同一个模型、工具或共享上下文可以承担多个角色。所以，一个读取日历、保存偏好并发送提醒的智能体，三个角色都承担了。

## 六条通路

耦合通路是一条有方向的信息流：一个模块提供信息，另一个模块用这些信息作决策或更新状态。

| 通路 | 流动的信息 |
|---|---|
| S→A | 当前输入到达行动。每个智能体系统都有这条基本路径。 |
| S→M | 感知到的或用户提供的证据被纳入记忆。 |
| M→A | 保留的信息引导行动的决策：时机、内容、执行接口、承诺或保持沉默。 |
| A→S | 行动引导感知：下一步观察什么，或者检查一次行动是否达到了预期效果。 |
| M→S | 保留的先验（之前形成的认识）引导感知：关注什么，或者如何解释新的输入。 |
| A→M | 行动上下文、记录或结果被保存到记忆中。 |

在插件中，当模块 Y 的一个事件用到了模块 X 的一个事件，通路 X→Y 就出现了。[事件模型](/HALO/zh-cn/architecture/events/)说明智能体如何写明这一点。

## 五个证据步骤

会自我改进的服务会改变自己的机制，也就是它的提示词、规则、技能、策略或模型。论文要求一条证据链，从服务自己的记录一直延伸到它之后用上的一次修订。HALO 对每一步分别判断。

1. **记录。** 服务保存自己行动的记录，供以后使用。
2. **结果。** 服务获得并保存关于这些行动的后续证据，例如一条回复、一个评分、一次纠正或一个任务结果。
3. **归因。** 一个结果被关联到它所涉及的决策，并用来检查或纠正协助。即时检查也算数，即使什么都没有保存。
4. **修订。** 服务自己对机制作出持久的改变。固定机制所使用的事实和偏好属于内容，不算修订。由用户或开发者写下的改动，也不算服务自己的修订。
5. **后续使用。** 之后的步骤在修订后的机制下运行。

通路覆盖和证据链是两个独立的维度。论文发现，在报告了全部通路的已审阅工作中，没有一项同时报告修订，而证据链完整的工作，则有一些通路没有说明。因此，HALO 把两者列在不同的表格中，不把它们合成一个分数。
